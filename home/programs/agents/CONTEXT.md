# Work philosophy

- Prefer simple solutions over unnecessary complexity.
- Write self-documenting code with clear names and straightforward control flow.
- Add comments only to explain non-obvious details, not to narrate the code.
  Task names, dates, and implementation summaries belong in PR descriptions.
- Avoid unnecessary abstractions. Prefer functional approaches over OOP unless
  the task or user calls for it. A little duplication is cheaper than the wrong
  abstraction.
- Follow YAGNI: solve the current problem instead of speculative future needs.
- Use the unslop skill for code cleanup when it is available.
